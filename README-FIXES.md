# Правки з аудиту — що зроблено і як накотити

Розпакуй цей zip ПРЯМО В КОРЕНЬ проєкту (туди, де лежать папки `backend/` і
`frontend/`) з підтвердженням заміни файлів — шляхи всередині архіву
збігаються зі структурою репозиторію, нічого вручну переносити не треба.

## ⚠️ Один ручний крок (zip не може видаляти файли)

Видали вручну: **`frontend/src/components/App.jsx`**
Це мертвий, застарілий дублікат справжнього `frontend/src/App.jsx` (459
рядків, не імпортується ніде, останній раз оновлювався до того, як у
реальний файл додали тему/Cloudinary/i18n). Архів файлів на видалення не
містить — тільки додає/замінює.

## Що саме змінено (8 пунктів)

| Файл(и) | Що зроблено |
|---|---|
| `backend/app/routers/venues.py` | Підпис Cloudinary-завантаження тепер включає `allowed_formats=jpg,jpeg,png,webp` — Cloudinary сам відхилить файл іншого формату, бо зміна цього значення ламає підпис |
| `frontend/src/uploadImage.js` | Передає `allowed_formats` далі в Cloudinary; додана клієнтська перевірка розміру (10 МБ) — **але** це не серверний захист: Cloudinary не має сигнатурного параметра для обмеження розміру, жорсткий ліміт можна виставити тільки в налаштуваннях upload preset у Cloudinary-консолі (поза межами файлів) |
| `backend/app/main.py` | Swagger `/docs`, ReDoc і `/openapi.json` вимикаються, коли `VERCEL_ENV=production` (Vercel виставляє цю змінну сам); у preview-деплоях і локально лишаються доступними для дебагу |
| `frontend/vercel.json` | Додано `headers` з CSP, HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy. CSP навмисно не максимально суворий (`'unsafe-inline'` для style/script) — я не можу прогнати весь білд локально, щоб перевірити, що суворіший CSP нічого не зламає, тож це консервативний, безпечний старт, а не фінальна версія |
| `frontend/public/robots.txt`, `frontend/public/sitemap.xml` | Нові файли. Sitemap навмисно містить тільки головну сторінку — сторінки закладів (`?venue=123`) динамічні, з бази, а не статичні маршрути, тож коректний sitemap з усіма 76 закладами має генеруватись при білді з даних БД, а не лежати статичним файлом, який миттєво застаріє |
| `frontend/src/api.js` | 422-помилки від Pydantic (масив об'єктів) тепер коректно перетворюються в читабельний рядок замість `[object Object]` |
| `frontend/src/App.jsx`, `frontend/src/components/Hero.jsx`, `frontend/src/i18n/translations.js` | Прибрано "миттєве порожньо": текст "База поки порожня" тепер показується тільки якщо заклади СПРАВДІ завантажились і їх 0, а не поки триває перший `fetch` (додано `hero.venuesLoading`) |
| `frontend/src/components/ReviewForm.jsx`, `frontend/src/i18n/translations.js` | Кнопка "Залишити відгук" і раніше коректно блокувалась без імені/оцінки (DOM-валідація працювала) — але людина не бачила, чого саме бракує. Тепер під кнопкою з'являється конкретна підказка |

## Перед деплоєм

Всі JS/JSX-файли перевірені `esbuild` на синтаксис, Python — `ast.parse`,
JSON/XML — валідатором. Але я не ганяла повний `npm run build` і не
тестувала живий деплой цих змін — зроби звичайний `git diff`, подивись
очима і прогони `npm run build` локально перед пушем.
